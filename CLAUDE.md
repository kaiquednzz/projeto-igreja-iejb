# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Static website (pt-BR) for the church IEJB (Araçariguama, SP). Plain HTML/CSS/JS — no build step, package manager, linter or tests. Deployed via GitHub Pages (`CNAME` → iejb.com.br). Run it by opening `index.html` or with VS Code Live Server (port 5501, see `.vscode/settings.json`).

## Structure

- `index.html` — single-page landing site; sections (`#brand`, `#quem-somos`, `#programacao`, `#galeria`, `#ministerios`, `#depoimentos`, `#eventos`, `#cta`, `#localizacao`) are anchored from the nav. Also holds the SEO JSON-LD blocks.
- `pages/` — `galeria.html`, `privacidade.html`, `termos.html`. They use `../` relative paths for CSS/JS/images.
- `404.html` (root) — GitHub Pages serves it for any missing URL at any depth, so it uses root-absolute paths (`/estilo/...`), not `../`. `noindex`.
- `estilo/icones.css` + `estilo/fontes/` — **generated** Font Awesome subset (only the icons the site uses). Never edit by hand; see "Icons" below.
- `ferramentas/` — Python helpers (Pillow / fonttools): `gerar-miniaturas.py` (photo thumbnails) and `gerar-icones.py` (icon subset). Not loaded by the site.
- `estilo/style.css` — one shared stylesheet (~3400 lines) for all pages, ordered: design tokens (`:root`) → base → utilities → buttons → header → home sections (each with its own media queries next to it) → floating UI → gallery page → legal pages → motion.
- `script/script.js` — shared script, loaded with `defer` on every page (menu, reveal, header/scroll UI, lightbox, daily verse, events filter, service worker registration). `script/visita.js` (index only) holds the visit-conversion features; it relies on globals declared in `script.js`. `script/versiculos.js` is the verse list.
- `manifest.webmanifest` + `sw.js` — PWA (pages, CSS and JS network-first; images stale-while-revalidate; only `ok`, non-redirected responses are cached; no cache versioning needed). The SW precaches `./` on install (the first visit never goes through it), stores navigations without their query string (`?utm`/`?fbclid` don't multiply copies) and, offline, falls back to the cached home — redirecting only when the home is cached and isn't the URL that failed, to avoid a loop. The manifest `id` stays `./index.html` (the old `start_url`) so existing installs keep their identity. The `?v=2` on local CSS/JS links was a one-time bust of the old service worker's cache — don't bump it on every change.
- `images/` (`pag-galeria/` holds gallery photos), `sitemap.xml` (pages + their images, `lastmod`), `robots.txt`, Google verification HTML.

## Things to know

- **Events are hardcoded HTML.** To add an event, copy an `.eventos-grid` block in `index.html` `#eventos` and set `data-data="YYYY-MM-DD"` (optional: `data-imagem` for the `Event` JSON-LD image; `data-local-nome` + `data-local-cidade` when it happens outside the church). Inside: `.data` (`p.data-dia`, `p.data-mes`, `p.data-semana`), `.textos` (`p.evento-categoria`, the title in `h4`, description `p`) and `.horario p` lines. `script.js` hides past events and sorts the rest; `visita.js` adds countdown, calendar (.ics), share and `Event` JSON-LD from the same markup. Time is parsed from the `.horario p` text (e.g. `19h30`).
- **Service times live in one place for the scripts:** the `.cultos-grid[data-dia][data-hora][data-nome]` cards in `#programacao`. The hero "próximo culto", sticky mobile bar, planeje-sua-visita and calendar buttons all derive from them (`proximaOcorrencia` / `proximoInicio` in `script.js`). **But for SEO the hours are also written as static text** (Google reads it without running JS), so when a time changes update all of: the cards, `<meta name="description">` and `og:description` in `index.html`, the `Church` JSON-LD `description`, the FAQ answer about hours, the "Horários" card in `#localizacao`, `.footer-cultos` in every page's footer (`index`, `pages/*`, `404.html`) and the text baked into `images/og-iejb.jpg`. There is deliberately no `openingHoursSpecification` (services aren't business hours).
- **NAP (name, address, phone) must be identical everywhere** — Google matches it against the Business Profile: "IEJB - Igreja Evangélica do Jardim Brasil", "Rua Ceará, 128 - Jardim Brasil", "Araçariguama - SP, 18147-000". It appears in the JSON-LD (`@id https://iejb.com.br/#igreja`, which the `Event` JSON-LD references as organizer), `#localizacao`, the FAQ, `.footer-endereco` and `ENDERECO_IEJB`/`LOCAL_IEJB` in `visita.js`.
- **SEO per page:** each page has its own `<title>`, description, `canonical` (`https://iejb.com.br/` with the trailing slash for the home) and Open Graph (`images/og-iejb.jpg`, 1200×630). Internal links keep `index.html` so the site also works from `file://`.
- **Daily verse:** picked by date from `window.VERSICULOS` (stride coprime with list length, so no repeats within a cycle); opened state and streak are in localStorage.
- **Ministry cards** carry `id="ministerio-<nome>"`/`data-ministerio`; the quiz and planner read their text from the DOM.
- Dynamic sections (`#planeje`, `#quiz`) are `hidden` in HTML and revealed by JS. The global `[hidden]{display:none!important}` rule in `style.css` is relied on.
- **Reveal animations:** elements with class `.reveal` get `.visible` from an IntersectionObserver in `script.js`, which plays the `revelar` CSS *animation* (not a transition): a short rise with a blur that clears. It animates `translate`/`filter`, so hover effects must keep using `transform` (and `transition`) to avoid conflicts; adding another `animation` to a `.reveal` element replaces `revelar`. The stagger is automatic: elements that enter the viewport in the same observer batch get `--atraso` 0, 0.07s, 0.14s… (no container list to maintain). Only put `.reveal` on "leaf" blocks — never on a whole `<section>` (its background would fade in from nothing) or on a wrapper whose children also have `.reveal` (movements add up and opacity multiplies). Section titles (`h2`/`h3`) all carry `.reveal`. `.reveal` is only hidden under `html.js` (set by an inline script in each `<head>`; `script.js` removes it if the file fails to load or IntersectionObserver is missing), so content never stays invisible without JS. The hero has no `.reveal`: it is the LCP element, so its entrance only slides (`heroSobe`, no opacity/blur).
- **`script.js` is shared across pages**, so every feature in it must guard against missing elements (galeria/termos/privacidade lack most home-page sections).
- **Testimonials typewriter:** `script.js` replaces each `<p>` under `.depoimentos-grid` with two stacked spans (the `<p>` is a one-cell grid): `.texto-molde` holds the full text in transparent color (reserves the height and is what screen readers read) and `.digitando` (`aria-hidden`) gets re-typed from `dataset.textoCompleto` when scrolled into view. The cursor is `.digitando::after`; `.digitado` on the `<p>` removes it.
- **Page transitions** use the CSS View Transitions API (`@view-transition` and `::view-transition-old/new(root)` with `slide-in`/`slide-out` keyframes in `style.css`, plus `<meta name="view-transition">` in page heads). Cross-page navigations depend on this.
- **Images:** WebP, max 1600px. Every content `<img>` has `width`/`height` (no layout shift; `img { height: auto }` in the base keeps the ratio when CSS sets only the width), `loading="lazy"` + `decoding="async"` below the fold, and `srcset` with the `-400.webp`/`-800.webp` thumbnails plus `sizes` (for `object-fit: cover` boxes, `sizes` must account for the crop: a portrait photo in a landscape box needs more pixels than the box width). After adding photos run `python3 ferramentas/gerar-miniaturas.py` (skips existing ones) and copy the `srcset` pattern from a gallery `<img>`. The home hero uses `iejb-principal-retrato.webp` on portrait phones (CSS media query + matching `<link rel="preload" media>`). Header/footer use `images/logo-iejb-pequeno.png`; the full `logo-iejb.png` is for JSON-LD.
- **Icons:** Font Awesome 6.7.2 Free is no longer loaded from a CDN. `ferramentas/gerar-icones.py` scans the HTML/JS for `fa-solid|fa-regular|fa-brands fa-<name>` and writes a subset font + `estilo/icones.css` (~8 KB instead of ~320 KB). **When you use a new icon, re-run it** (instructions in the script's docstring) or the icon renders blank. Icons always get `aria-hidden="true"`.
- **Accessibility conventions:** skip link `.pular` → `main#conteudo` on every page; `html { scroll-padding-top }` keeps anchors and Tab focus below the fixed header (and `scroll-padding-bottom` while the mobile bar shows) — don't add `scroll-margin` to sections, they'd add up; the focus ring color is the `--foco` token (brand red on light backgrounds, white on dark ones — add new dark sections to that selector list in `style.css`, next to `SECOES_ESCURAS`); decorative CSS `content` uses the alt-text syntax (`content: '+' / ''`); live regions (`aria-live`) must exist and be visible *before* their text changes.
- One `<h1>` per page: the hero's is `.sr-only`, and the header/footer logo text is a `<span class="logo-texto">`.
- Commit messages follow conventional-ish prefixes in Portuguese (`feat:`, `fix:`, `style:`).

## Visual system (iOS/Apple style)

- **Tokens first:** colors, fonts, glass, shadows, radii and easing curves are custom properties in `:root`. `--mola` is a spring curve (`linear()` with a `cubic-bezier` fallback) used for anything that should feel physical. No dark mode (owner's decision).
- **Fonts:** Playfair Display for headings, the system font stack (`--fonte-texto`: SF Pro on Apple devices) for everything else, Oswald only for the logo text. Montserrat is no longer loaded; the daily-verse image (canvas) uses the system font too.
- **Header** is a fixed floating glass capsule (`position: fixed`), so the first section of every page needs ~120px top padding. The glass lives on `header::before`, never on `header` itself: an ancestor with `backdrop-filter` would stop the mobile menu panel (a child) from blurring the page. `script.js` toggles `header.sobre-escuro` (dark glass, white text) by checking what is behind the header with `elementsFromPoint` against `SECOES_ESCURAS` — **add any new dark section to that list**. Pages that open on a dark hero (`index`, `galeria`) start with `class="sobre-escuro"` in the HTML to avoid a flash. The logo PNG is white; on the light header it is tinted brand red with `filter: var(--logo-vermelho)`.
- **Nav pill:** `script.js` creates `.nav-indicador` inside `nav` and moves it (`--x/--y/--w/--h`) to the active link. Active = the last menu section whose top has passed 40% of the viewport (sections not in the menu keep the previous link lit). On subpages it sits on `a[aria-current="page"]`. Below 900px the nav becomes a glass dropdown (`nav.ativo`) that closes on Escape, link click or tap outside.
- **Buttons** are all in the "Botões" section of `style.css`: a shared base in `:where(...)` (zero specificity, so component rules can resize freely) plus exactly one color group — principal (filled red), secundário (red tint) or vidro (glass over photos/dark). For a new button, either give it one of the ready-made classes `.botao-principal` / `.botao-secundario` / `.botao-vidro`, or add its selector to the base list and to one group. The groups use `:is()`, whose specificity is that of its most specific argument, so an element must never match two groups. Press feedback is `:active { transform: scale(.95); transition-duration: .12s }` — it springs back with `--mola` on release.
- **Glass cards:** the "Material de vidro" selector list (or the ready-made `.cartao-vidro` class) gives light cards translucency + bright border + top highlight + shadow *without* `backdrop-filter` (nothing moves behind them, so blur would only cost GPU). Real `backdrop-filter` is reserved for things with content passing behind: header, menu, floating buttons, toast, mobile bar, lightbox, hero chip/buttons and the ministry captions over photos.
- **Animation budget:** anything that loops forever must animate only `transform`/`translate`/`scale`/`opacity` (runs on the GPU, e.g. the green pulse of the hero chip is a separate `::after` circle) or stop by itself (the daily-verse button "breathes" 3 times when its card becomes `.visible`). Animating `box-shadow`, `filter` or sizes in a loop repaints every frame and drains phone batteries. The global `prefers-reduced-motion` block at the end of `style.css` already shortens everything.
- **Hero chip** `#proximo-culto` starts as `.aguardando` (`visibility: hidden`, with a `&nbsp;` to reserve its height) and `script.js` fills it, so the hero never jumps. It is hidden entirely under `@media (scripting: none)`, together with the other JS-only controls.
